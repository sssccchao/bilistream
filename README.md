# 哔哩哔哩直播亲密度助手

油猴脚本 **1.6.0**。每次随机发送一个 1–10 的数字或目标房间的可用表情，再点赞 30 次并等待上报；当前房间模式共发送 10 条。跨房间模式在一个直播间页面读取粉丝牌及各房间任务进度，只补未完成的任务。两种模式均不模拟 K 键，也不操作弹幕输入框。切换到其他标签页后会继续运行，但浏览器冻结页面时会暂停。

## 安装或更新

1. 浏览器安装 [Tampermonkey（油猴）](https://www.tampermonkey.net/)。
2. 新建脚本，或打开已有的「哔哩哔哩直播亲密度助手」。
3. 用 `bilistream-intimacy.user.js` 的**全部内容**替换编辑器内容，按 **Ctrl+S** 保存。
4. 刷新直播间。请替换原脚本，不要同时启用多个版本。

使用不需要 Node.js，也不用手动填写账号密码或 Cookie。数字弹幕和当前房间点赞复用页面内置方法；表情与跨房间任务使用浏览器当前登录状态，通过网页接口发送请求。

## 使用

先登录直播间，等待页面加载。在 **任务** 标签页点击 **开始全部** 即可运行。上报确认、限速和 **检测内置接口** 位于 **设置** 标签页。底部状态与停止按钮在所有标签页均可用。

若要在一个页面处理粉丝牌房间，点击 **读取粉丝牌**，检查列表与已开播数量，再点击 **开始粉丝牌任务**。脚本读取全部分页并按真实房间号去重，先处理已开播房间，再处理未开播房间。它会在每个房间开始前读取任务进度，跳过已完成的弹幕和点赞；已开播但粉丝牌未点亮时，先以 30 次点赞点亮，再补足每日的 10 条弹幕（随机数字或随机表情）和 300 次点赞。每轮结束后重新读取任务接口，确认计数增长才继续。未开播且已点亮的房间会补完弹幕；实测未开播房间的点赞请求虽返回成功，却未计入任务，因此点赞留待开播。未开播且未点亮的房间暂缓处理。整个过程无须打开其他直播间页面。

- **只发弹幕**：随机发送 10 条数字或表情，间隔至少 2 秒；收到发送确认后才继续。
- **房间列表**：读取粉丝牌后默认展开，点击房间数量一行可折叠或展开。任务更新保持当前折叠状态。
- **只点赞**：通过内置方法点赞 300 次，等待最后一批上报完成；保留现有草稿和输入焦点。
- **停止**：停止后续调用。页面已经排队或发出的请求仍可能完成，无法撤回。
- **折叠**：点击右上角 −，收成页面左下边缘的「亲密度 +」标签；点击可展开。

## 界面

1.6.0 参考 [LAPLACE Chatterbox](https://github.com/laplace-live/chatterbox) 的配置面板风格，采用灰白底色、绿色按钮、下划线标签页和紧凑折叠分组。配色读取直播页的主题变量，支持宿主页提供的深色主题。

- **任务**：当前进度、当前房间操作和可折叠的粉丝牌列表。
- **表情**：按房间设置随机数字/随机表情，读取目标类别的表情预览。
- **设置**：上报确认、限速信息和内置接口检测。

拖动面板右边缘可调整宽度，范围随窗口大小限制。标签页、宽度、主面板折叠状态会在刷新后恢复。折叠入口继续位于左下边缘，运行时变为绿色；切换标签页、调整宽度或折叠面板都不会启停任务。

本次参考界面模式，使用现有单文件脚本的 DOM/CSS 实现。调研和对应关系见 [Chatterbox 风格记录](docs/research/2026-09-27-chatterbox-style.md)。

## 随机发送模式

1. 打开 **表情** 标签页，在房间下拉框中选当前房间。需要配置其他粉丝牌房间时，先点击 **读取粉丝牌**，再选择目标房间。
2. 选择 **随机数字** 或 **随机表情**，再返回 **任务** 标签页，点击 **开始全部**、**只发弹幕** 或 **开始粉丝牌任务**。
3. **读取房间表情** 用于预览，可以省略；随机表情任务开始前会自动读取目标房间表情及权限。点击任一可用预览也会切换到随机表情，随机池仍包含该房间所有可用表情。

随机数字每条独立从整数 1–10 中抽取；随机表情每条独立从目标房间已解锁的 **UP主大表情** 和 **房间专属表情**（兼容名称 **房间专属**）中抽取。数字与表情均允许重复，次数和发送间隔不变。通用表情、活动表情、小表情及未解锁项不会进入随机池。

每个房间独立配置模式；房间专属表情只发送到对应房间。未配置的房间默认随机数字。发送模式保留到页面刷新，任务执行期间不能更改。界面标签页、宽度与主面板折叠状态保存在浏览器本地并在刷新后恢复；任务进度和运行状态不会自动恢复。房间列表仍可随时展开或折叠。

表情发送采用与网页相同的 `msg=emoticon_unique`、`dm_type=1` 协议，经 WBI 签名提交 `/msg/send`，不会把表情名称当成普通文字。开始房间任务前重新读取权限；没有可用表情时停止并提示切换随机数字，不回退到其他类别。收到接口成功确认后才计数和继续点赞；网络结果未知时禁止直接重启，以免重复发送。

已在登录页面确认表情列表接口可用，并用模拟响应验证完整发送流程。尚未实测表情的亲密度到账；跨房间模式会继续核对任务计数，未增长则停止。当前房间模式需要在粉丝团面板核对。

运行时暂时不要手动发弹幕或点赞，也不要同时运行其他点赞脚本，以免混入额外操作。开始后可以切换到其他标签页或窗口，脚本会继续执行；切换直播间房间号仍会停止。后台延迟不会导致集中补发，操作始终串行并遵守点赞冷却。

跨房间模式通过 `fansMedal/panel` 获取列表，通过 `GetActivatedMedalInfo` 读取每日任务；弹幕调用 `/msg/send`，点赞调用 `likeReportV3`。点赞每 400 毫秒计时一次，每 15 次提交一批，请求使用当前网页播放器的 WBI 签名和 CSRF 参数。脚本把接口 `code: 0` 当作请求被接受；只有重新读取的每日任务计数增长，才把操作记为任务进度。若服务端没有计入，脚本停止，避免继续无效上报。

浏览器可能降低后台定时器频率，因此后台完成时间可能变长，无法保证每秒 3 次。标签页被浏览器冻结、丢弃，浏览器关闭或电脑休眠时，普通网页脚本无法持续执行。脚本不会主动唤醒标签页、抢焦点或修改浏览器设置。参见 [Chrome 后台定时器说明](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)。

## 点赞频率和确认进度

点赞间隔为 `max(334ms, 房间冷却毫秒数 + 25ms)`，调度和上报等待可能使实际间隔更长。因此每秒最多 3 次；房间要求更慢时自动放慢。冷却为 350ms 的房间，计划间隔至少 375ms。总用时取决于房间冷却、分批上报和网络响应，通常需要两分钟或更久。

面板分三种计数：

| 计数 | 含义 |
| --- | --- |
| 弹幕进度 | 当前房间模式：数字弹幕的内置成功回调，或表情接口成功回执；跨房间模式：任务接口中的已完成次数 |
| 点赞进度 | 当前房间模式：内置方法已接收的本地点赞；跨房间模式：任务接口中的已完成次数 × 30 |
| 上报确认 | 本轮点赞请求返回 `code: 0` 后，按 `click_time` 累计；点亮粉丝牌的 30 次也计入本轮上报 |

当前房间模式只观察页面自己发出的点赞请求，兼容 `fetch` 和 XMLHttpRequest，以及 URL 查询参数和表单请求体；不主动复制或重发请求。上报进行中会暂缓新增点赞，避免旧批次的清空操作影响新计数。每 30 次点赞后、任务结束前，都等待本地队列清空及上报确认。跨房间模式则直接请求目标房间接口，不依赖当前房间的点赞组件。

跨房间模式会核对每日任务计数，当前房间模式以发送确认及点赞上报为准。粉丝牌总亲密度显示可能与任务计数更新时机不同；需要时可在粉丝团面板核对。

## 异常处理

- 找不到支持的内置组件时停止，可以先等待加载或刷新。取消了旧版的手动绑定输入框和发送按钮，也不会退回模拟键盘操作。
- 输入框已有草稿或回复对象时，弹幕任务停止以保护内容；请手动处理后再开始。
- 未登录、禁言、发送冷却或需要验证码时停止，请先在页面处理。
- 前台数字弹幕成功回调等待上限为 20 秒；点赞上报等待上限为 30 秒。某次等待期间进入后台时，该次等待从开始计时放宽至最多 3 分钟，回到前台也保留这次宽限。失败、频繁、格式变化或网络状态不明时停止，不自动重试。
- 停止或出错时，如果还存在未确认操作，必须刷新直播间后才能再次启动，以免上一轮的迟到回执混入新任务。
- 停止后页面原有的点赞上报仍可能执行。刷新会重置脚本进度，再次开始会重新执行全部指定次数。
- 跨房间模式再次启动时会重新读取服务端任务计数，从尚未完成的弹幕或点赞继续。请求结果未知或请求被接受却没有增加任务计数时，脚本停止并要求先核对再刷新；不会盲目重发。

这些是 B 站内部方法，可能随页面更新变化。调研依据见 `docs/research/2026-09-22-native-interfaces.md`。

## 开发验证

```powershell
npm ci
npm test
npm run check
npm run test:browser
```

单元测试用模拟的 Vue 组件契约与本地响应验证：10×30 顺序、弹幕成功回调、按冷却限速、上报确认、失败停止、草稿保护、后台继续和迟到回执。跨房间测试模拟粉丝牌分页、WBI/CSRF、任务读取、点亮、断点续跑、未开播处理及接口成功但任务不增长的情形。随机内容测试覆盖数字端点与重复抽样、每条重新抽取表情、权限变化、发送协议、发送确认、失败和未知结果停止、按房间隔离配置。Edge 浏览器测试覆盖隐藏页面状态下的当前房间流程、fetch/XHR 上报观察、折叠位置，以及随机表情发送、房间列表折叠、跨标签页停止、鼠标拖拽宽度、刷新后的界面偏好恢复、窄窗口布局与宿主页深色主题。

2026-09-23 在用户授权的登录 Edge 中做了小范围实测：跨房间弹幕请求成功；目标粉丝牌未点亮时，第一轮 30 赞只使粉丝牌点亮；点亮后的一条弹幕和 30 赞分别使任务计数从 0/10 增至 1/10。另一个未开播房间的弹幕计数增长，但 30 赞上报返回成功后点赞任务仍为 0/10。实测未运行所有粉丝牌房间的完整任务。

可选运行 `node tests/live-native-smoke.cjs`：在独立、未登录的 Edge 中加载真实直播页，检查当前原生点赞方法与脚本的兼容性。测试会在请求出网前拦截点赞并返回模拟结果，同时阻止所有其他非只读请求；不会发送真实点赞。它不能验证登录后的服务端接受情况或亲密度到账。
